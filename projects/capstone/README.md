# Projeto final — Capstone D2FS

O projeto final deve demonstrar domínio do fluxo completo, não quantidade de funcionalidades. Escolha um problema pequeno, dados acessíveis e uma métrica verificável.

## Arquitetura mínima

```text
Fonte de dados
  -> ingestão e validação
  -> transformação e armazenamento
  -> análise ou modelo
  -> avaliação
  -> CLI, API ou aplicação web
  -> logs e documentação
```

## Entregáveis obrigatórios

- `README.md` com problema, público, arquitetura e instruções.
- Ambiente reproduzível com dependências declaradas.
- Pipeline de dados que possa ser executado novamente.
- Testes para ao menos uma transformação e um comportamento da aplicação.
- Baseline e métrica de avaliação.
- Demonstração por captura, vídeo curto ou aplicação acessível.
- Seção de limitações, riscos, custos e próximos passos.

## Rubrica de conclusão

| Critério | Peso | Evidência esperada |
|---|---:|---|
| Reprodutibilidade | 25% | Instalação e execução funcionam a partir do README |
| Dados | 20% | Origem, validação e transformações estão documentadas |
| Avaliação | 20% | Existe baseline, métrica e análise de falhas |
| Engenharia | 20% | Estrutura, testes, logs e tratamento de erros |
| Comunicação | 15% | Problema, resultado e limitações são compreensíveis |

O projeto está concluído com pelo menos 70% da rubrica e sem nota zero em qualquer critério.

## Sugestões de escopo

- Previsão de demanda com pipeline diário e painel simples.
- Classificação de chamados com análise de erros e API.
- Busca em documentos próprios com RAG e conjunto de avaliações.
- Controle de despesas com ingestão de CSV, categorização e relatório.
